A release a day, more or less.

## What happened

- Alibaba released [Qwen3.5](https://en.wikipedia.org/wiki/Qwen) with open weights on Monday.
- Anthropic released [Claude Sonnet 4.6](https://en.wikipedia.org/wiki/Claude_(language_model)) on Tuesday.
- Google released [Gemini 3.1 Pro](https://en.wikipedia.org/wiki/Gemini_(language_model)) on Thursday.
- Anthropic announced [Claude Code Security](https://www.anthropic.com/news/claude-code-security) on Friday as a limited research preview.

## What I make of it

The Security announcement is the one I read twice. At Developers Inc I worked on Qwiet AI's Autofix, a system that finds a vulnerability, proposes a patch, checks the patch for semantic correctness, and runs regression tests before a human sees it. Ocular, the analysis side, used graph neural networks over code property graphs to find the source-to-sink paths in the first place.

Claude Code Security appears to do the same job with a general model in place of the specialized stack. I have opinions about that. A general model will find more classes of bugs than a graph model trained on known patterns. It will also produce more false positives and it will be harder to explain why it flagged something. The Autofix pattern still applies: generate a fix, verify it independently, gate it behind a human. Whoever builds the verification step well will win this category. The model that proposes the fix is not the hard part.

## Gemini 3.1 Pro

I moved the Scout orchestrator to 3.1 Pro on Friday afternoon and reran the eval suite. Routing accuracy went up a little. Cost went up a little. I am keeping it for the orchestrator only. The nine specialist agents stay on Flash. This is the pattern I keep coming back to. Spend on the one agent that decides, save on the ones that execute.

Sonnet 4.6 and Qwen3.5 both go into the model bench for the migration translation job. Results next week if they are interesting.

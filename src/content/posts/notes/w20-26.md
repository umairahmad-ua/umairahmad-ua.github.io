The trackers I read all said the same thing. No frontier release this week. Claude Code added an [agents view and a goal command](https://code.claude.com/docs/en/whats-new/2026-w20). That was the news. So this note is about work instead.

## The reconciliation step

Our migration agents translate a client's stored procedures and ETL jobs into BigQuery SQL. The translation agent is not the hard part. Gemini reads decade-old T-SQL well enough. The hard part is proving the result matches. We run both systems, compare row counts and aggregates, and a validation agent writes up any difference. A human approves each cutover batch.

This month a batch passed reconciliation and was wrong. Row counts matched. Sums matched. A date column had shifted by one day for about two percent of rows because of a timezone default that differs between the two systems. The aggregate we checked was a count by month and the shift was small enough to hide inside it.

The fix was boring. We added per-column distribution checks and a sample-level diff on a random thousand rows. The validation agent now writes a table of columns with their match rate instead of a paragraph saying the batch looks fine. A paragraph is what a model produces when you ask it to summarize. A table is what a reviewer needs.

## Why I am telling you this

Every vendor spent the spring saying agents can migrate your data platform. They can. The agent is cheap. The trust is expensive. Reconciliation, dual-run periods, and a rollback plan are what let a finance team sign off. The model made the translation fast. It did not make the finance team less careful, and it should not.

The agents view in Claude Code is small and useful. It shows every running agent in one place. I want that view for our own agents in Agent Engine. The traces exist. The single screen does not, yet.
